Problem

Every module instantiates itself at import, so nothing can be loaded without live configuration — and @glidepath/auth builds a second connection pool while the first sits unused.

Solution

Delete the module-level db and auth constants. The server app reads configuration once and passes it down; createServer returns the app and a separate line starts it.

  • · Leverage: one interface, whole runtime
  • · Locality: configuration read in one place
  • · Second pool disappears
  • · SKIP_ENV_VALIDATION stops being load-bearing
  • · First real test surface in repo
  • · Two adapters justify the db seam

Problem

The build config describes a compiled module; the task graph runs a source-only one. Neither reading is wrong, but both are written down, so the plumbing tells two stories.

Solution

Option A is the smaller move and fits the current setup: the packages are consumed as source and bundled by tsdown. Delete the inert options, add a types:check script to each package.

  • · Every module checked on own terms
  • · Config stops describing absent behaviour
  • · env/web.ts gets strict rules
  • · Turbo caching becomes truthful

Not candidates — small untruths in the plumbing

Each is a dependency or option that claims something the code does not do. No diagram earns its place; fold them into whichever candidate you take first.

  • · apps/web depends on @hookform/resolvers — the app uses @tanstack/react-form. Unused.
  • · dotenv is a dependency of apps/web, packages/auth, and the root. None import it.
  • · zod is a dependency of packages/db and packages/auth. Neither imports it.
  • · apps/server/tsconfig.json sets jsx and jsxImportSource: hono/jsx. The server has no JSX.
  • · The root package.json lists workspaces, which pnpm ignores in favour of pnpm-workspace.yaml.
  • · README.md omits packages/env and packages/config from the project structure.

Top recommendation

Give the server a composition root

It is the root cause under three other candidates. Once configuration is passed in rather than read at import, the drizzle.config.ts workaround (4) has an obvious home, SKIP_ENV_VALIDATION stops being load-bearing (6), and the workspace gets a seam it can test through (5) — which it has none of today.

It also fixes a live defect on its own: @glidepath/auth constructs a second connection pool while the one exported by @glidepath/db is never used.
